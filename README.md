# W-DCA-Planner

> 给定「每月往这些标的投这些钱」的假设，计算不同年限下的收益结果，
> 并让**修改假设的成本接近于零**。

一个 FIRE（财务独立 / 提前退休）计算器。核心不是「算得多准」，而是
**改一个参数就能立刻看到全部结论怎么变** —— 加一个标的、换一个定投额、
提前两年停止定投，成本都应该是几秒钟的事。

## 快速开始

需要 **Python ≥ 3.12**、[uv](https://docs.astral.sh/uv/)、**Node ≥ 20**。

```bash
# 1. 后端（终端 A）
uv sync
uv run uvicorn backend.main:app --reload --port 8000

# 2. 前端（终端 B）
cd frontend
npm install
npm run dev          # → http://localhost:5173
```

打开 <http://localhost:5173>，选「美股」即可开始。默认配置已经填好一组
能立刻算出结果的参数，**打开就能看到数**，不是一片空表。

### 生产模式（单进程）

```bash
cd frontend && npm run build     # 产出 frontend/dist
uv run uvicorn backend.main:app --port 8000
# → http://localhost:8000 前后端同源，无需 Vite
```

后端启动时若发现 `frontend/dist` 存在就会自动挂载它。

## 它算什么

### 积累期

逐月推进：定投注资 → 价格推进 → 派息 → 扣股息税 → 处理税后股息
（再投资 / 累积为现金）→ 现金计息 → 每年末再平衡。

支持**分段式定投** —— 每一段有各自的月投额和持续时长，首尾相接。
所以「前 10 年每月投 2000，然后停投，让它自己长」是一等公民，
而不是需要绕开模型的特例。

持续时长按「年」「个月」两格填，**两格是加数，不是进位位**：
`7 年 25 个月` 照收，等于 9 年 1 个月，当场把实际值标出来；只填年、
只填月也都行。唯一的真值始终是一个整数（总月数），两个格子只是它的
两种面额 —— 所以不需要「填了年就要求月 ≤ 11」那类只为保护书写约定
而存在的校验规则。

每段还有一个**定投频率**：每几个月投一次，默认 1（每月），可填 3（按季）、
6（按半年）。金额是「**每期一笔整的**」，首月必投，之后每隔 N 个月一笔 ——
**不是把一笔摊薄到中间的月份上**。填 3 就是每三个月买一笔，现金流是断续的；
摊薄会把按季买入抹成连续注资，和真实的操作对不上。所以界面上这个词也跟着
频率走：频率不是 1 的时候写「每 3 个月投入额」，不写「月投额」—— 每三个月
投 900 不是「月投 900」，字数不多，但界面说错话比不说更糟。

### FIRE 层

| 口径 | 公式 | 含义 |
|---|---|---|
| FIRE Number | 年支出 × 倍数（25× = 4% 规则） | 现在就该有的**全部**本金 |
| Coast FIRE | FIRE Number ÷ (1+g)^n | 现在只需存够这么多，其余交给复利 |
| Barista FIRE | (年支出 − 兼职收入) × 倍数 | 兼职顶掉一部分开销 |

外加里程碑达成时间、取款期模拟（能撑多少年）、提取率反推（想撑 N 年
每年最多取多少，**闭式解**，不用二分迭代）、以及增长率降档的敏感度。

### 为什么是确定性外推，不是蒙特卡罗

蒙特卡罗会给出一个概率分布，看起来很专业，但它把「不确定性」这个
问题**转移**了而不是回答了 —— 你仍然要自己决定该信 50% 分位还是 10% 分位。

本项目选择：**给一条确定的线，然后明说它只在假设成立时成立**，
再用敏感度表告诉你假设差一点会差多少。

## 数据获取

在组合里输入一个代码，前端就自动去抓它的历史行情，并从中**反推**增长率、
股息率、股息增长率三个参数 —— 用户不必自己去查。界面上标出数据截至哪一天、
**来自哪个源**，以及（当这份数据来自本地已有缓存时）一个「更新数据」按钮。

### 两个来源并行，谁快谁先渲染

| 内容 | 来源 | 实测 |
|---|---|---|
| 价格（快路径） | stockanalysis.com `/api/symbol/…/history` | 约 **1.2 秒**，稳定 |
| 价格（慢路径） | Nasdaq `api.nasdaq.com/…/historical` | 约 **50 秒**，且约一半的请求直接超时 |
| 派息记录 | stockanalysis.com `/api/symbol/…/dividend` | 约 1 秒 |
| 标的名称 | Nasdaq `…/info`，或**离线代码清单** | 见下 |

两个来源**同时**发出去，谁先回谁先渲染；Nasdaq 后到且成功，就覆盖掉
stockanalysis 那份，界面上的「来源」也跟着改成 Nasdaq。

串行的话用户要盯着转圈等近一分钟才看见第一个数字，所以不是一个备一个。

> 本机实测（2026-09）：Nasdaq 慢到**不可用**，连 QQQ / SPY / VOO 这种最常见的
> 代码都会超时。慢路径留着是因为 stockanalysis 那份是官网渲染图表自用的
> **未公开接口**，没有稳定性承诺 —— 留着它，快的那份哪天没了也不至于全瞎。

### 离线代码清单

输入代码后要**立刻**告诉用户这个代码存不存在。这要求判断在毫秒级且不依赖
网络，所以清单是**离线快照**：`backend/data/symbols_us.txt`，11,366 个标的
（5,628 只个股 + 5,738 只 ETF），随仓库带走，运行时零网络。

它有三个用途：

1. **即时判断代码是否存在** —— 不在清单里就提示「可能拼错了，也可能是新上市」
2. **给快路径提供标的名称** —— 快路径故意不调 Nasdaq 的 info 接口（那个要
   几十秒），没有名字可填，正好用清单里的
3. **零成本** —— 内存查表，比一次网络往返快三个数量级

⚠️ 清单是快照，会过时。所以那条提示是**软**的：确认无误仍可手输参数，
**永远不会据此拒绝用户**。没有清单文件时 `known` 为 `null`，界面干脆不提示
—— 空清单和没有清单是两回事，前者会把每个用户都冤枉一遍。

> 关于清单来源：本想用 Nasdaq Trader 的官方目录（`nasdaqlisted.txt` /
> `otherlisted.txt`），但那个 CDN 挂在 Incapsula 后面，本机实测一个文件要
> 243 秒、另一个反复断在 316KB / 349KB，多试几次就开始回机器人挑战页。
> 退而用 SEC 的 `company_tickers.json` 也不行 —— 它列的是**注册发行人**，
> ETF 基本不在里面（QQQ / SCHD / VOO / VTI / AGG / VXUS / BND 全部缺失）。
> 一份「查不到 QQQ」的清单比没有清单更糟，它会主动冤枉用户。
> 最后落在 stockanalysis 的 screener 接口上，两个接口各约 2 秒且稳定可达。

重新生成（代码目录变化很慢，不需要经常跑）：

```bash
uv run python backend/scripts/build_symbol_universe.py
```

> 试过但不可用的：**stooq** 会在响应里塞一段 JS 工作量证明（反爬），
> 程序拿不到数据；**Yahoo Finance** 从中国大陆被硬墙。**Nasdaq Trader 的
> 代码目录**见上。这几条都别回头再试。

### 缓存口径：以**最近一个已收盘交易日**为准

这是这个模块最要紧的一条规则。

```
缓存里最后一根 K 线的日期  ==  最近一个已收盘交易日  →  直接用，不发请求
                            !=                        →  才去抓
```

关键在于右边这个值**一天之内是常数**。于是同一天里，用户反复改参数、
来回切标的、把 SCHD 删了又加，都不会产生任何网络请求 —— 第一次之后
全是本地命中。实测第二次取数是 **17 ms**（首次约 2.2 s）。

缓存**按来源各存一份**（`SCHD.stockanalysis.json` / `SCHD.nasdaq.json`）。
只存一份就得挑一个丢一个：要么丢了快路径那份（下次输入又得等），要么丢了
Nasdaq 那份（永远换不成更好的数据）。

「最近一个已收盘交易日」的判断带一个 **16:30 ET 的结算缓冲**：交易日当天
盘中，算出来的是**前一个**交易日；收盘结算之后才算当天。否则盘中去抓，
会拿到一根还在变的当日 K 线，缓存下来就再也刷不掉了。

时区按 `America/New_York` 算，并且走真实的 NYSE 日历（含耶稣受难日、
六月节，以及「元旦落在周六则不补休」这类细则），不看本地时区。

### 一个刻意的偏向

判断「今天是不是交易日」时，**宁可误判为交易日，也不误判为休市**。

因为代价不对称：

- 误判成交易日 → 多发一次请求，拿到一样的数据，**下次自愈**
- 误判成休市 → 缓存永远不失效，**数据永久陈旧且无人察觉**

所以临时休市（国葬、飓风）一律不建模 —— 它们没法从规则推出来，而错了
的代价又落在「永久陈旧」这一侧。日历只收录**可推算**的固定规则。

### 抓取模式的费用率必须为 0

ETF 的管理费是每天从基金资产里直接扣的，**已经体现在历史价格里**。
抓取模式下再按费用率扣一次就是重复计算，所以此时的 `expense_ratio`
被强制为 0，界面上那个输入框也会锁住、只作展示（决策台账 A23）。

### 抓不到怎么办：两种失败必须说成两句不同的话

都表现为「拿不到价格」，但对用户的含义**正好相反**：

| 情形 | 后端标记 | 界面怎么说 |
|---|---|---|
| 一个字节都没收到 | `failure: unreachable` | 「数据源暂时不可达……这不代表代码有问题」 |
| 收到了答复，里面没这个标的 | `failure: unknown_symbol` | 「数据源查不到这个代码，请确认代码是否正确」 |

早先两者共用一句话，于是数据源一抖，界面就去**指控用户填错了代码** ——
用户会真的去改，而代码本来是对的。冤枉人比不解释更糟。

前端**不靠匹配中文文案**来判断该等还是该报错，而是读 `failure` 字段：
`unknown_symbol` 是权威答复，立刻报；`unreachable` 先等等另一个来源，
免得快路径一抖动就报错、而下一秒数据就回来了。

另外，stockanalysis 对不存在的代码直接回 **404**（实测 `e/ZZZZ` 回 200 空表、
`e/ZZZZZZ` 回 404，两种都表示查无此标的）。所以对这个端点，404 算**答复**、
不重试 —— 否则用户拼错一个字母要白等两轮超时，最后还被告知「网络不可达」。
Nasdaq 那个端点不这么解读：对它的 404 无法与「接口抽风」区分，多试一次更稳。

### 抓不到就用手输

不编数。示例参数会标明自己是示例，并提供重试按钮和手输入口。

## 三条设计纪律

这三条不是风格偏好，是**可执行的约束**，且都有测试兜底。

### 1. `engine.py` 零 IO

无 `print`、无 `open`、无网络、不读系统时间。所有外部输入（包括当前日期）
必须由调用方显式传入。

`backend/tests/test_engine.py::test_engine_performs_no_io` 会用 **AST 扫描**
源码，发现禁用函数调用或禁用模块导入就直接失败。将来有人顺手加一句
`print` 调试，CI 会拦住。

### 2. 前端不做任何计算

FIRE Number、Coast 折现、组合混合增长率 —— 全部在后端算好再返回。
否则同一套口径就有了两个实现，早晚会不一致。

> 这条纪律的直接体现：`result.fire` 是后端算好的 FIRE 汇总，
> 而不是前端拿 `annual_expense * multiple` 乘一下。

### 3. 每月折算用几何，不用算术

```
月利率 = (1 + 年化)^(1/12) − 1        ✅
月利率 = 年化 / 12                     ❌
```

算术折算下 `0.07/12` 复利 12 次等效年化 **7.23%**，30 年**高估约 6.6%**。
几何折算才能让 12 个月精确复利回年化值，也才能和 `本金 × (1+g)^n`
的闭式解严格对上。

## 测试

```bash
uv run pytest -q                      # 后端：195 个测试
cd frontend && npm run check:render   # 前端：14 组渲染自检
cd frontend && npm run check:e2e      # 前端：135 项浏览器端到端自检
```

### 后端（195 个）

1. **数值验收**（AC-1 ~ AC-5）—— 界面上有数不算，能对上闭式解才算
2. **业务规则** —— 定投展开（含**定投频率**）、再平衡、股息税、费用率陷阱、里程碑
3. **架构约束** —— 引擎零 IO、只依赖 models 与 datetime
4. **交易日历与缓存** —— 假日表对公开日历、盘中外时点、结算缓冲、
   「第二次请求不再发网络请求」、两个来源各存各的缓存
5. **失败分类** —— 「没有答复」与「答复就是没有」必须报成两种不同的
   结果；404 不重试
6. **代码清单** —— 没有清单时不许提示；空清单等同于没有清单
7. **配置一致性** —— 计划里提到组合中不存在的标的必须被拒
8. **数据源自洽** —— 同一来源的历史末价与它自报的现价对不上时，
   这份数据一律不用（含读缓存时再查一遍）
9. **股息口径** —— 派息频率按完整自然年的笔数数出来（不是按间隔反推，
   「月度 + 季度补充」的 16 笔/年不会被压成 12）；已宣告未派发的股息
   不进 TTM；测量区间不足 3 年就不报增长率，并**标记**这是「测不了」

其中最有价值的一个自检点：**当组合增长率 == 通胀率（实际收益率 0）时，
安全提取率恰好等于 1/N** —— 撑 25 年就是 4.00%。这个解析解由闭式
公式与逐年正演模拟**双向验证**，相对误差 < 1e-12。

### 前端（渲染自检）

`npm run check:render` 用 **SSR 真渲染**结果类组件，每个组件跑
**真实数据 + 空数据**两组。

构建只证明「编译得过」，证明不了「渲染得出来」—— 模板里一次越界访问
（比如 `result` 为 null 时读 `last.total_value`）编译期完全看不出来，
运行时却会白屏。空数据那一组尤其关键：用户删光标的、清空里程碑时
走的就是这条路径。

> 这个自检第一次跑就抓到一个真 bug：里程碑标签写死 `$100,000`，
> 切到日元显示时变成「$100,000 ¥100,000」—— 标签和金额自相矛盾。

### 前端（浏览器端到端自检）

`npm run check:e2e` 用 **Playwright 驱动系统已装的 Chrome**（`channel: 'chrome'`，
不额外下载浏览器），在真浏览器里跑完一整套操作：进主界面 → 加/删/改标的 →
核对计划合计 → 缩放平移点选曲线 → 输入代码触发抓取。

**需要后端（8000）与前端 dev server（5173）都在跑。** 前端地址可用
`E2E_URL` 覆盖；Vite 默认绑在 `[::1]:5173`，所以要用 `localhost`
而不是 `127.0.0.1`。

要这一层是因为渲染自检**跑不了事件**。而下面这些恰恰是「编译通过、
首屏也正常、但功能是坏的」：

- 浮层挡住了画布 → 图表拖不动（真实发生过的 bug）
- `wheel` 监听被注册成 passive → 缩放时整页跟着滚
- 输入空代码的草稿行 → 整个应用报错
- 勾选框点下去没反应 —— 值的改变是「点击的默认动作」，`click` 事件里
  读到的还是旧值（`change` 里才是新的）
- 卡片收起了，里面的输入框还能被 Tab 选中
- 股息增长率报 0 时，界面把「测不了」说成「不增长」—— 两者数值相同、
  含义相反。这条文案的颜色和盒子也在这一层量（灰的，不是红的；不顶出卡片）
- 持续时间的月份框里打「144」，三个数字打不完 —— 每敲一下都被规范化
  重写。这条**必须逐字打**才能测到：`fill()` 是一次性写入，正好绕过它
- 打完「144」再点年份框，框里的 `0` 被 `onfocus` 改成 `12`，用户接着
  打 `7` 落在后面就成了 **127 年**（光标按旧文本定位）。同样是鼠标用户
  真会遇到的问题
- 定投频率填 3，引擎收到的必须是**断续的**现金流 —— 每 3 个月投 300、
  投 5 年，累计投入是 6,000。摊薄成每月投 100 的话会算出 18,000，
  数字更大、看着也「合理」，只有对着笔数才看得出来
- 界面上的措辞要跟着频率变：频率为 1 时断言「每月投入额」，为 3 时断言
  「每 3 个月投入额」—— 只写 `/月投/` 会**子串命中**后者，永远绿

断言一律锚在**具体某张标的卡**上，不用「第一个 `.quote-row`」这种相对
定位 —— 早先正是这种写法让两条断言长期读错了对象却一直是绿的。

布局断言量的是**像素**，而且跑**三个视口**（1440 / 1100 / 900）：同权重的
CSS 规则靠声明顺序决胜，输了既不报错也不警告，`vite build` 照样成功 ——
而这类 bug 在宽屏下往往是绿的。
